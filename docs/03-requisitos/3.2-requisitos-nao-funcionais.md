## 3.2 Requisitos Não Funcionais

Os requisitos não funcionais definem como o sistema deve funcionar: segurança, desempenho, usabilidade, confiabilidade e conformidade com a LGPD. A versão original tinha 30 requisitos (RNF01 a RNF30). Nesta revisão, cada requisito recebeu a indicação de escopo, que mostra se ele vale para o MVP ou se fica para uma versão seguinte (backlog). A Tabela 8 apresenta a lista completa.

As alterações feitas foram:

(i) **Movidos para o backlog:** o RNF03 (uso de Redis para busca de produtos) e o RNF20 (modo escuro). No MVP, a busca usa índices no PostgreSQL e o cache do TanStack Query no front-end, e o Redis entra se a busca ficar lenta com o crescimento da base. O modo escuro foi adiado porque o protótipo tem apenas o tema claro; o Tailwind CSS permite adicioná-lo depois sem refazer as telas.

(ii) **Meta de disponibilidade ajustada:** o RNF28 pedia 99,99% de disponibilidade ao ano, o que equivale a menos de uma hora fora do ar. Essa meta exige servidores pagos e redundância, incompatíveis com a hospedagem gratuita do MVP. A meta do MVP passou a ser 99%, e a de 99,99% ficou registrada para a versão de produção.

(iii) **Novo requisito:** o RNF31 exige que as permissões de cada papel sejam conferidas na API, e não apenas escondidas na interface. Essa regra já aparecia na arquitetura técnica e no padrão MVC.

(iv) **Correções de texto:** foram corrigidos erros de digitação no RNF04, RNF09, RNF11, RNF15 e RNF16, sem mudar o sentido.

Os requisitos escritos para o aplicativo mobile (RNF17, RNF18 e RNF22) foram mantidos. No MVP web, eles se aplicam ao uso do KeepIT pelo navegador do celular: o consumo de dados (RNF17) depende do tamanho das fotos e das respostas da API; o consumo de bateria (RNF18) é baixo porque a aplicação não roda em segundo plano; e a compatibilidade (RNF22) é verificada nos navegadores do Android 10 e do iOS 15 em diante.
